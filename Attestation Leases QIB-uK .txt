FIX-G — Enforcing Attestation Leases in require_attestation

Status: Implemented, compiled, and test-validated (17/17 tests passing on Rust 1.75, cargo test). Builds directly on the FIX-H2 capability-generation patch already applied to this file.

The bug

AttestationCap in attestation.rs carried a valid_until_ns field and helper methods (is_valid(), assert_cap_not_expired()) — but the actual authorization gate the rest of the kernel calls, require_attestation() in capability.rs, never consulted any of it. It only checked capability kind and liveness:

// OLD (buggy) require_attestation — kind + liveness only, no expiry check pub fn require_attestation(pid: u32) -> Result<(), KernelError> { let table = CAP_TABLE.lock(); let has_attest = table .iter_live() .any(|c| c.owner_pid == pid && matches!(c.kind, CapabilityKind::Attestation { .. })); if has_attest { Ok(()) } else { Err(KernelError::AttestationRequired) } } 

A minimal repro of that exact logic confirms the consequence directly — an attestation minted with a lease that expired 4000ns earlier still passes:

OLD require_attestation: Ok (BUG: lease expired at 1000, now is 5000, but access was still granted) 

So a task whose attestation had lapsed — but which nobody had gotten around to explicitly revoking — kept passing every check gated on require_attestation, silently defeating the entire point of a temporal lease.

The fix

Move valid_until_ns onto the capability the kernel actually checks. CapabilityKind::Attestation now carries { enclave_id, valid_until_ns } directly, instead of the expiry living only in a separate AttestationCap wrapper that require_attestation never looked at.

require_attestation now takes now_ns and compares it. It returns:

AttestationRequired if pid has no attestation capability at all.

AttestationExpired if pid has one (or more), but all of them have now_ns >= valid_until_ns.

Ok(()) only if at least one live, unexpired attestation capability exists for pid.

Splitting AttestationRequired from AttestationExpired is deliberate: a caller handling "never attested" (send them through first-time attestation) needs to behave differently from "attested before, lease lapsed" (send them through renewal) — the old code couldn't distinguish these at all.

Added renew_attestation so a lease can be extended in place without revoking and re-minting the capability (which would needlessly churn its FIX-H2 generation counter and trigger a scheduler preempt for no real reason — renewal is not revocation).

This sits directly on top of the FIX-H2 patch already in this file: FIX-H2 made "is this capability live" a reliable, slot-scoped fact instead of a comparison against a global counter; FIX-G adds the time dimension that liveness alone was never meant to cover.

What did not change

AttestationCap in attestation.rs (the wrapper type with is_valid()/assert_cap_not_expired()) is untouched by this patch. Once require_attestation checks the lease directly off CapabilityKind::Attestation, that wrapper becomes largely redundant — worth a follow-up to either delete it or make it the single source of truth instead of duplicating valid_until_ns in two places. Flagging rather than fixing here, since collapsing them touches attestation.rs call sites this patch didn't need to change.

Clock source. require_attestation and renew_attestation take now_ns/new_valid_until_ns as plain parameters rather than reading a kernel clock internally, consistent with how the rest of qib-muk threads time explicitly from the caller (e.g. the scheduler's tick timestamp) rather than each module reading its own clock.

FIX-H2 behavior. All ten pre-existing generation-scoping tests still pass unmodified in behavior — only the Attestation variant's construction was updated to supply valid_until_ns, since that field is now mandatory.
