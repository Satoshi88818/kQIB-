kQIB Fleet v3.1 — Fix #1: Static Kafka Partition Assignment

This is the full kqib workspace with issue #1 fixed and validated by actually compiling and running the test suite (Rust 1.75, cargo test --workspace, all green — see the run log at the bottom). Everything else from v3 is carried over unchanged except where noted in "Incidental fixes" below.

The bug (recap)

PartitionWorker's consumer used a unique group.id per worker (qib-control-partition-{partition_id}) but called subscribe(). subscribe() puts a consumer into Kafka's dynamic group-rebalance protocol, and since each worker was the only member of its own group, the broker's group coordinator handed it every partition of the topic — not just the one implied by its name. All N workers ended up consuming all messages for all robots, each with its own independent, inconsistent RobotTwinState map. The central V3-5 claim — "a robot_id always hashes to the same partition, so each worker has exclusive ownership, no locks needed" — never actually held.

The fix

Swap subscribe() for consumer.assign(&TopicPartitionList) — static, explicit partition ownership that bypasses the group-rebalance protocol entirely. A statically-assigned consumer only ever reads the partitions you hand it, regardless of group.id; the per-partition group.id is kept purely so offsets commit and resume independently per partition, which was the one part of the original design that was fine.

New module qib-cloud-backend/src/partition.rs holds the pure, broker-independent pieces of this so they're unit-testable without a live Kafka cluster:

build_partition_assignment(topic, partition_id) — builds the single-partition TopicPartitionList a worker statically assigns itself to, resuming from the last committed offset (Offset::Stored).

validate_partition_count(expected, actual) — refuses to start if KAFKA_PARTITIONS doesn't match the topic's real partition count on the broker (checked via fetch_metadata in main() before any assignment happens). With static assignment there's no coordinator to fall back on, so a silent mismatch would leave partitions unowned or double-assigned.

expected_partition_ids(total) — the reference partition set used to assert full, non-overlapping topic coverage in tests.

main.rs now: fetches real broker metadata for TELEMETRY_CONTROL_TOPIC → validates it against KAFKA_PARTITIONS → spawns one task per partition that builds its assignment via build_partition_assignment and calls consumer.assign(&tpl) instead of consumer.subscribe(...).

Tests added for this fix

qib-cloud-backend/src/partition.rs (unit tests, cfg(test) module) and qib-cloud-backend/tests/partition_tests.rs (integration-style, same public API main.rs uses):

a worker's assignment names exactly one partition, on the right topic

assignment resumes from Offset::Stored

negative partition ids are rejected

validate_partition_count catches both directions of mismatch (fewer real partitions than configured, and more)

the core invariant: across a 6-worker deployment, the six static assignments are pairwise disjoint and exactly cover partitions 0..6 — precisely the property the old subscribe() bug violated (every worker got every partition, the opposite of disjoint).

Everything here is broker-independent by design, so it runs in plain cargo test — no Kafka cluster required. The metadata-fetch/validation call in main() itself is integration-level (needs a real broker) and is exercised structurally, not live, for the same reason.

Incidental fixes required to get a clean build

These were pre-existing defects in the v3 codebase, unrelated to issue #1, that blocked cargo check/cargo test and had to be fixed to actually validate anything:

qib-cloud-backend/Cargo.toml had a circular self-dependency — [dev-dependencies] qib-cloud-backend = { path = ".", features = ["test-utils"] } — referencing a test-utils feature that didn't exist anywhere. Removed; split the crate into a proper lib.rs (for partition, twin, metrics, sign_command) + main.rs (binary) so tests can depend on the lib normally.

qib-edge-proxy/src/main.rs: m: &impl rdkafka::message::BorrowedMessage<'_> — BorrowedMessage is a concrete struct, not a trait, so impl Trait syntax doesn't compile. Changed to &rdkafka::message::BorrowedMessage<'_>.

FutureRecord::to(...) with only .payload(...) set (DLQ sends in both main.rs files) doesn't have enough type information for rdkafka to infer the key type K. Pinned it explicitly: FutureRecord::<(), [u8]>::to(...).

qib-muk/src/ipc.rs used [const { IpcMessage::Empty }; RING_SIZE] (inline-const array repeat), which needs a newer rustc than this project's toolchain supports. Replaced with the long-stable const-item-repeat form (const EMPTY: IpcMessage = ...; [EMPTY; N]), same result, no MSRV bump required.

Postcard was used directly (postcard::Error) in both error.rs files without postcard being a direct dependency of those crates — added it to qib-edge-proxy/Cargo.toml and qib-cloud-backend/Cargo.toml.

None of these five change behavior; they're what "actually run cargo test" surfaces that a read-through doesn't.

Toolchain note

This was validated with apt's Rust 1.75 (Ubuntu 24.04), which is older than what several current crate versions require. Cargo.lock pins a handful of transitive dependencies down to versions compatible with 1.75 and this MSRV (fixed 1.24.0, az 1.2.1, half 2.4.1, ed25519-dalek 2.1.1, uuid 1.10.0, zeroize 1.8.1, indexmap 2.2.6, proc-macro-crate 2.0.0, base64ct 1.7.3, proptest 1.4.0). On a newer toolchain (1.85+) these pins are unnecessary — cargo update would move them forward — but they don't change any of the logic above.

//! Lock-free, zero-copy IPC between the microkernel and the edge proxy. //! No heap allocation; all types use fixed-point to stay no_std clean. use core::sync::atomic::{AtomicBool, AtomicUsize, Ordering}; use fixed::types::I20F44; pub const RING_SIZE: usize = 256; /// All numeric fields use fixed-point to prevent f64 from leaking into no_std. #[repr(C)] pub enum IpcMessage { Empty, /// (temp_fixed, z_vel_fixed) Telemetry(I20F44, I20F44), Command { action: u8, duration_sec: u32, valid_until_ns: u64, issued_at_ns: u64, min_epoch: u64, max_epoch: u64, sequence: u64, command_id: [u8; 16], }, } pub struct SharedRingBuffer { pub messages: [IpcMessage; RING_SIZE], pub head: AtomicUsize, pub tail: AtomicUsize, /// Set by microkernel when a push is dropped due to full buffer. pub overflow_flag: AtomicBool, } impl SharedRingBuffer { pub const fn new() -> Self { const EMPTY: IpcMessage = IpcMessage::Empty; Self { messages: [EMPTY; RING_SIZE], head: AtomicUsize::new(0), tail: AtomicUsize::new(0), overflow_flag: AtomicBool::new(false), } } /// Wait-free push. Returns false and sets overflow_flag on full buffer /// instead of silently dropping — callers can emit a safety telemetry event. pub fn push(&mut self, msg: IpcMessage) -> bool { let head = self.head.load(Ordering::Relaxed); let next = (head + 1) % RING_SIZE; if next == self.tail.load(Ordering::Acquire) { self.overflow_flag.store(true, Ordering::Release); return false; } self.messages[head] = msg; self.head.store(next, Ordering::Release); true } /// Wait-free dequeue for the microkernel scheduler. pub fn pop(&mut self) -> Option<IpcMessage> { let tail = self.tail.load(Ordering::Relaxed); if tail == self.head.load(Ordering::Acquire) { return None; } let msg = core::mem::replace(&mut self.messages[tail], IpcMessage::Empty); self.tail.store((tail + 1) % RING_SIZE, Ordering::Release); Some(msg) } pub fn take_overflow(&self) -> bool { self.overflow_flag.swap(false, Ordering::AcqRel) } }

//! 1 ms isochronous tick. All safety decisions happen here, before Kafka. //! V3-4: Z-acceleration (jerk) trip added alongside Z-velocity limit. use crate::ipc::{IpcMessage, SharedRingBuffer}; use fixed::types::I20F44; use qib_schema::{WATCHDOG_DEADLINE_NS, Z_VELOCITY_HARD_LIMIT}; // V3-4: Acceleration (delta-velocity per tick) hard limit. // At 1ms ticks, this is effectively m/s² units. // 5.0 units/tick → triggers on sudden impact faster than velocity alone. pub const Z_ACCEL_HARD_LIMIT: I20F44 = I20F44::from_bits(5 << 44); pub struct RobotState { pub temp: I20F44, pub halted: bool, pub cooling_until_ns: u64, pub current_epoch: u64, pub next_seq: u64, pub last_tick_ns: u64, pub last_ack_id: Option<[u8; 16]>, /// V3-4: Previous tick's Z velocity for acceleration calculation. pub last_z_vel: I20F44, } impl RobotState { pub fn new(now_ns: u64) -> Self { Self { temp: I20F44::ZERO, halted: false, cooling_until_ns: 0, current_epoch: 1, next_seq: 0, last_tick_ns: now_ns, last_ack_id: None, last_z_vel: I20F44::ZERO, // V3-4 } } } /// Called every 1 ms from the bare-metal scheduler interrupt. pub fn tick( state: &mut RobotState, rx: &mut SharedRingBuffer, tx: &mut SharedRingBuffer, now_ns: u64, ) { // ── 0. Hardware Watchdog ───────────────────────────────────────── let elapsed = now_ns.saturating_sub(state.last_tick_ns); if elapsed > WATCHDOG_DEADLINE_NS && !state.halted { state.halted = true; // Emit watchdog-trip telemetry (status sentinel via negative z_vel) let _ = tx.push(IpcMessage::Telemetry(state.temp, I20F44::ZERO)); } state.last_tick_ns = now_ns; // ── 1. Process Commands from Edge Proxy ─────────────────────────── while let Some(msg) = rx.pop() { if let IpcMessage::Command { action, duration_sec, valid_until_ns, issued_at_ns: _, min_epoch, max_epoch, sequence, command_id, } = msg { if now_ns > valid_until_ns { continue; } if state.current_epoch < min_epoch || state.current_epoch > max_epoch { continue; } if sequence < state.next_seq { continue; } state.next_seq = sequence + 1; state.last_ack_id = Some(command_id); match action { 1 => state.cooling_until_ns = now_ns + (duration_sec as u64 * 1_000_000_000), 2 => state.halted = true, _ => {} } } } // ── 2. V3-4: Hardware Fast-Path Safety — Velocity + Acceleration ─ // // We read the hardware register once and compute both checks atomically. // Acceleration (jerk) detection catches crashes *before* velocity // crosses the hard limit — essential for sub-millisecond impact detection. let current_z_vel = I20F44::from_num(read_hardware_z_vel()); // V3-4: delta-velocity over one 1ms tick = instantaneous acceleration proxy let z_accel = (current_z_vel - state.last_z_vel).abs(); if (current_z_vel > I20F44::from_num(Z_VELOCITY_HARD_LIMIT) || z_accel > Z_ACCEL_HARD_LIMIT) && !state.halted { state.halted = true; // Velocity OR acceleration limit tripped } state.last_z_vel = current_z_vel; // V3-4: carry forward for next tick // ── 3. IPC Overflow → Safety Telemetry Flag ─────────────────────── let ipc_overflow = rx.take_overflow(); // ── 4. Emit Telemetry to Edge Proxy ─────────────────────────────── let temp_fixed = state.temp; let z_fixed = current_z_vel; let status_msg = if ipc_overflow { IpcMessage::Telemetry(temp_fixed, I20F44::from_num(-1.0)) // overflow sentinel } else { IpcMessage::Telemetry(temp_fixed, z_fixed) }; let _ = tx.push(status_msg); } fn read_hardware_z_vel() -> f64 { // Replaced by actual hardware register read in production 0.0 }

//! Per-robot Bayesian Digital Twin with EWMA variance and Brier-score //! circuit breaker. Self-contained; no global mutable state. use qib_schema::{ BREAKER_RECOVERY_GOOD_READINGS, BRIER_DELTA_THRESHOLD, BRIER_Z_CONFIDENCE, EWMA_LR, VARIANCE_EPSILON, }; use std::sync::atomic::{AtomicBool, AtomicU32, Ordering}; pub struct RobotTwinState { pub robot_id: u32, pub temp_mean: f64, /// EWMA variance accumulator (Welford online algorithm) pub m2: f64, /// Circuit breaker: open = commands halted for THIS robot only pub breaker_open: AtomicBool, /// Consecutive good readings since last breaker trip (auto-recovery) pub good_readings: AtomicU32, pub last_ack_id: Option<[u8; 16]>, pub next_sequence: u64, } impl RobotTwinState { pub fn new(robot_id: u32, initial_temp: f64) -> Self { Self { robot_id, temp_mean: initial_temp, m2: 0.0, breaker_open: AtomicBool::new(false), good_readings: AtomicU32::new(0), last_ack_id: None, next_sequence: 0, } } /// EWMA-Welford update. Variance stays bounded; never diverges. pub fn update(&mut self, temp: f64) { let delta1 = temp - self.temp_mean; self.temp_mean += EWMA_LR * delta1; let delta2 = temp - self.temp_mean; self.m2 = (1.0 - EWMA_LR) * self.m2 + EWMA_LR * (delta1 * delta2); } /// Standard deviation with epsilon floor to prevent Z-score divide-by-zero. pub fn std_dev(&self) -> f64 { self.m2.sqrt().max(VARIANCE_EPSILON) } /// Evaluate Brier-score breaker. Returns true if tripped this call. pub fn evaluate_breaker(&self, predicted_temp: f64, actual_temp: f64) -> bool { let delta = (predicted_temp - actual_temp).abs(); let z_score = delta / self.std_dev(); if z_score > BRIER_Z_CONFIDENCE && delta > BRIER_DELTA_THRESHOLD { self.breaker_open.store(true, Ordering::SeqCst); self.good_readings.store(0, Ordering::SeqCst); return true; } if self.breaker_open.load(Ordering::SeqCst) { let good = self.good_readings.fetch_add(1, Ordering::SeqCst) + 1; if good >= BREAKER_RECOVERY_GOOD_READINGS { self.breaker_open.store(false, Ordering::SeqCst); self.good_readings.store(0, Ordering::SeqCst); } } false } pub fn is_breaker_open(&self) -> bool { self.breaker_open.load(Ordering::SeqCst) } pub fn next_seq(&mut self) -> u64 { let s = self.next_sequence; self.next_sequence += 1; s } }

//! V3-5 FIX: static, deterministic per-partition ownership. //! //! ## The bug //! The original implementation gave every `PartitionWorker` a *unique* //! consumer `group.id` (`qib-control-partition-{partition_id}`) and called //! `consumer.subscribe(&[TOPIC])`. `subscribe()` puts a consumer into //! Kafka's dynamic group-rebalance protocol: the broker's group coordinator //! decides which partitions each *group* owns, and distributes them among //! that group's members. Because each worker was the lone member of its own //! group, the coordinator handed it **every** partition of the topic — not //! just the one implied by its name. //! //! In practice this meant all N workers each consumed all messages for all //! robots, so: //! - Every robot's telemetry was processed redundantly by every worker, //! each with its own independent (and inconsistent) `RobotTwinState`. //! - The core V3-5 claim — "a robot_id always hashes to the same //! partition, so each worker has exclusive ownership, no locks needed" //! — did not hold, because ownership was never actually partitioned. //! //! ## The fix //! Use `consumer.assign(&TopicPartitionList)` for **static** partition //! ownership instead of `subscribe()`. `assign()` bypasses the //! group-rebalance protocol entirely: a consumer only ever reads the //! partitions it is explicitly given, regardless of `group.id`. Each //! worker keeps its own `group.id` purely so offsets are committed and //! tracked independently per partition; that part of the original design //! was fine; `subscribe()` vs `assign()` was the actual defect. //! //! This module holds the pure, broker-independent logic for building and //! validating that static assignment so it can be unit tested without a //! live Kafka cluster. use anyhow::{anyhow, Result}; use rdkafka::topic_partition_list::TopicPartitionList; use rdkafka::Offset; /// Builds the `TopicPartitionList` a single worker should statically /// `assign()` itself to: exactly one partition, resuming from whatever /// offset is already committed under that worker's `group.id` (falling /// back to the consumer's `auto.offset.reset` policy if none exists yet). pub fn build_partition_assignment(topic: &str, partition_id: i32) -> Result<TopicPartitionList> { if partition_id < 0 { return Err(anyhow!( "partition_id must be non-negative, got {partition_id}" )); } let mut tpl = TopicPartitionList::new(); tpl.add_partition_offset(topic, partition_id, Offset::Stored) .map_err(|e| anyhow!("failed to build partition assignment: {e}"))?; Ok(tpl) } /// Confirms the topic's actual partition count on the broker matches what /// this deployment expects (`KAFKA_PARTITIONS`). Both are /// safety-relevant given each partition's twin state is assumed exclusive. pub fn validate_partition_count(expected: i32, actual: i32) -> Result<()> { if expected != actual { return Err(anyhow!( "KAFKA_PARTITIONS={expected} does not match actual topic partition count \ ({actual}); static assignment requires these to match exactly or some \ partitions will be left unowned" )); } Ok(()) } /// The exact, zero-indexed partition ids that `total` correctly-configured /// static workers should own between them. } // Wait for SIGINT/SIGTERM signal::ctrl_c().await.ok(); info!("Backend shutting down cleanly"); let _ = shutdown_tx.send(()); for h in worker_handles { let _ = h.await; } Ok(()) } fn current_time_ns() -> u64 { SystemTime::now() .duration_since(UNIX_EPOCH) .unwrap() .as_nanos() as u64 }
