kQIB Fleet v3.1 — Key Management Scope + Smaller Fixes (consolidated)

This is the single, consolidated deliverable for the full kqib workspace, now including the key management scoping and the three "smaller fixes" flagged previously (clock-sync overflow, unlink_shared_ring wiring, TWIN_STATE_TOPIC compaction visibility).

Everything here was actually compiled and tested — 82/82 tests pass across the whole workspace (cargo test --workspace, full log at the bottom), both binaries build and link with zero warnings.

Part 1 — Key management: scope and what's implemented

Current state (before this round)

SIGNING_KEY_SEED_HEX (backend) and TRUSTED_PUBKEYS (edge proxy) were both plain, static environment variables, loaded once at process startup. Rotating the backend's signing key meant: generate a new key, update the env var on the backend, redeploy the backend, and update TRUSTED_PUBKEYS on every single edge proxy (i.e. every robot) and restart each one. For a fleet of any size, that's a coordinated, error-prone, multi-system change for what should be a routine security operation.

Threat model (what rotation actually needs to defend against)

Backend key compromise. If the backend's signing key leaks, an attacker can forge commands (subject to the epoch/TTL/sequence checks already in place) until every edge proxy's trusted set is updated to exclude the compromised key. The slower that update propagates, the longer the exposure window.

Routine rotation. Independent of compromise, rotating keys periodically (e.g. annually, or per compliance policy) shouldn't require touching every robot by hand.

Partial rollout safety. During a rotation, some edge proxies will inevitably pick up the new trusted key before others. The backend should ideally be able to sign with both the old and new key during a transition window (this isn't implemented yet — see "Deferred," below).

What's implemented now: file-based sources with hot reload

This is the concrete, implementable-today increment: an external process (a Vault agent's file sink, a Kubernetes Secret volume mount refreshed by the platform, a runbook's scp, whatever the deployment already uses) writes key material to a file, and this codebase picks up changes to that file without a restart.

Backend (qib-cloud-backend/src/key_source.rs): a SigningKeySource trait behind load_signing_key(), with EnvSeedKeySource (unchanged original behavior), FileSeedKeySource (new — reads a 32-byte hex seed from SIGNING_KEY_FILE, re-reading on every load() call), and EphemeralKeySource (unchanged dev fallback). Priority: SIGNING_KEY_FILE > SIGNING_KEY_SEED_HEX > ephemeral. The backend currently only calls load() once per process lifetime (it doesn't re-sign already-issued commands), so file-based rotation here means "rotate on next restart" rather than truly hot — see "Deferred" for why a live backend-side rotation task wasn't added this round.

Edge proxy (qib-edge-proxy/src/trusted_keys.rs): a TrustedKeyStore (thread-safe, RwLock-backed) loaded via TrustedKeyStore::from_env(), supporting TRUSTED_PUBKEYS_FILE (new — one hex key per line, #-comments and blank lines skipped) with priority over the original static TRUSTED_PUBKEYS. A background task (spawn_reload_task, polling every TRUSTED_PUBKEYS_RELOAD_SECS, default 30s) re-reads the file and hot-swaps the trusted set — genuinely without a restart, proven by spawn_reload_task_actually_reloads_on_a_timer writing a new key to the file mid-test and asserting the running store picks it up. This side got the live reload (rather than just "on next restart") because a robot may run far longer between deployments than the central backend, making "restart every robot to rotate a key" a much bigger operational cost than restarting one backend process.

What's deliberately deferred, and why

Actual Vault / AWS / GCP Secrets Manager API integration. This environment has no network access to any secrets-management service and no credentials to test against — implementing this now would mean writing an integration I can't compile-test against the real service, which is exactly the kind of "looks plausible, unvalidated" work this whole exercise has been trying to avoid. The SigningKeySource trait (backend) and the equivalent structure on the edge-proxy side are the extension points: a VaultKeySource or AwsSecretsManagerKeySource slots in as another trait implementation without touching main.rs/handle_command/PartitionWorker call sites at all.

Dual-key transition window on the backend. Signing with both an old and new key during a rotation (so in-flight edge proxies mid-rotation still accept commands) isn't implemented — the backend currently signs with exactly one key, resolved once at startup. This is a real gap for a zero-downtime rotation, and would be the next concrete step if/when live backend-side key rotation (not just file-based "on next restart") is prioritized.

Polling-based (not event-driven) file watching. TRUSTED_PUBKEYS_RELOAD_SECS defaults to a 30-second poll rather than an inotify-based watch. This was a deliberate simplicity tradeoff — polling needs no extra dependency and is trivially correct — at the cost of up to 30 seconds of rotation propagation delay, which seemed like a reasonable trade for a security rotation (not a hot-path latency concern) but is easy to tighten later if needed.

Part 2 — Smaller fixes

Clock-sync EWMA overflow bound

ClockSync::synchronize computed cloud_issued_ns as i64 - proxy_received_ns as i64 and fed the result straight into drift_offset_ns * 9 with no bound — a corrupted or malicious issued_at_ns (e.g. near u64::MAX) could risk an i64 overflow. Fixed by subtracting in i128 first (so the initial cast itself can't silently wrap), clamping to ±60 seconds (MAX_PLAUSIBLE_DRIFT_NS, well outside any real clock skew but tight enough to catch corruption), logging a warning when clamping occurs, and using saturating_mul on the EWMA multiply as a defensive backstop. Tested with 4 new tests, including 10,000 iterations of alternating pathological input (repeated_pathological_input_never_overflows_or_panics) asserting the bound holds on every single call, not just eventually.

unlink_shared_ring wired into shutdown (opt-in)

shm::unlink_shared_ring existed but nothing outside tests ever called it — the edge proxy never cleaned up its shm segments on exit. Rather than unconditionally unlinking (which would silently discard any in-flight state if the microkernel side is expected to keep running or reattach independently — see the code comment for the full tradeoff), this is now opt-in via IPC_UNLINK_ON_SHUTDOWN=true, defaulting to false (leave segments alone, the safer default for a fleet where either side may restart independently). Tested with 3 flag-parsing tests plus a new integration test (unlink_makes_a_later_mapper_get_a_genuinely_fresh_ring) proving unlink_shared_ring actually removes the segment's name — a later mapper under the same name gets a fresh, empty ring rather than reattaching to the old one.

TWIN_STATE_TOPIC compaction visibility

warmup.rs's replay logic works correctly regardless of whether TWIN_STATE_TOPIC has Kafka log compaction enabled (it dedupes to the latest snapshot per robot itself), but without compaction the topic grows unbounded and replay gets slower every deployment cycle — a previously unstated assumption. Fixed: partition::topic_has_compaction_enabled queries the broker's cleanup.policy config via rdkafka's AdminClient::describe_configs, and main.rs logs a clear warning (with the exact kafka-configs command to fix it) if compaction isn't enabled — non-fatal, since this is a durability optimization, not a safety requirement. Tested with 4 pure unit tests against a hand-built ConfigResource, plus an integration test against rdkafka::mocking::MockCluster that honestly documents a real limitation: the mock broker's admin describe_configs isn't actually implemented (the request times out rather than returning data) — confirmed by direct probing before writing the test, not assumed. The test asserts the function fails closed within its own bounded timeout rather than hanging, which is exactly the behavior main.rs's non-fatal warning path depends on.

Recap: everything from earlier rounds

Issue #1 — PartitionWorker used a unique group.id per worker but called subscribe(), which handed every worker every partition via Kafka's dynamic group-rebalance protocol. Fixed with consumer.assign() for static ownership; validated against a real simulated broker (rdkafka::mocking::MockCluster), including a regression-guard test reproducing the original bug.

Issue #2 — a tautological scheduler test (|| { true }) fixed via an extracted, directly-testable trip-decision function; command signing and IPC dispatch wired end-to-end (previously silent no-op stubs), including fixing a latent &mut self soundness bug in the shared-memory ring buffer.

Twin-state persistence — worker restarts no longer silently reset every robot's breaker/variance/sequence state; TWIN_STATE_TOPIC is replayed on startup, with a subtler ordering bug (stale next_sequence from publishing the snapshot before command issuance) caught and fixed while wiring it in.

Issue #4 — a real Prometheus /metrics HTTP server replacing a stub that only logged a message; validated with both handler-level tests and a genuine bound-socket HTTP request.

//! Lock-free, zero-copy IPC between the microkernel and the edge proxy. //! No heap allocation; all types use fixed-point to stay no_std clean. //! //! ## Why `&self`, not `&mut self` //! This buffer is meant to live in memory shared across a real process (or //! address-space) boundary: one side is the sole producer, the other the //! sole consumer. Two independent contexts can never both hold Rust's //! `&mut SharedRingBuffer` to the *same* memory soundly — that's exactly //! the aliasing rule `&mut` exists to enforce, and it doesn't stop being //! true just because the two `&mut` references live in different processes. //! //! So `push`/`pop` take `&self` and use `UnsafeCell` for interior //! mutability. Soundness then rests on the single-producer/single-consumer //! (SPSC) *protocol*, not on the type system: the producer only ever writes //! `messages[head]`, the consumer only ever writes `messages[tail]`, and the //! `Release`/`Acquire` pair on `head`/`tail` ensures a slot is never touched //! by one side until the other has published (or already reclaimed) it. //! Violating the "exactly one producer, exactly one consumer" assumption //! (e.g. two tasks both calling `push`) is undefined behavior — this type //! does not protect against that, the same as any other SPSC ring buffer. use core::cell::UnsafeCell; use core::sync::atomic::{AtomicBool, AtomicUsize, Ordering}; use fixed::types::I20F44; pub const RING_SIZE: usize = 256; /// All numeric fields use fixed-point to prevent f64 from leaking into no_std. #[repr(C)] pub enum IpcMessage { Empty, /// (temp_fixed, z_vel_fixed) Telemetry(I20F44, I20F44), Command { action: u8, duration_sec: u32, valid_until_ns: u64, issued_at_ns: u64, min_epoch: u64, max_epoch: u64, sequence: u64, command_id: [u8; 16], }, } #[repr(C)] pub struct SharedRingBuffer { messages: [UnsafeCell<IpcMessage>; RING_SIZE], pub head: AtomicUsize, pub tail: AtomicUsize, /// Set by the producer when a push is dropped due to a full buffer. pub overflow_flag: AtomicBool, } // SAFETY: see the module-level doc. Concurrent access is sound only under // the SPSC protocol (one producer thread/process, one consumer thread/ // process), which is a caller obligation this type cannot enforce itself — // the same contract any SPSC ring buffer relies on. unsafe impl Sync for SharedRingBuffer {} impl SharedRingBuffer { pub const fn new() -> Self { const EMPTY: UnsafeCell<IpcMessage> = UnsafeCell::new(IpcMessage::Empty); Self { messages: [EMPTY; RING_SIZE], head: AtomicUsize::new(0), tail: AtomicUsize::new(0), overflow_flag: AtomicBool::new(false), } } /// Wait-free push. Returns false and sets overflow_flag on full buffer /// instead of silently dropping — callers can emit a safety telemetry event. /// /// Must only be called from the single producer side of this ring. pub fn push(&self, msg: IpcMessage) -> bool { let head = self.head.load(Ordering::Relaxed); let next = (head + 1) % RING_SIZE; if next == self.tail.load(Ordering::Acquire) { self.overflow_flag.store(true, Ordering::Release); return false; } // SAFETY: only the producer ever writes slot `head`. The Acquire // load above confirms the consumer has moved `tail` past this slot // (or never reached it yet), so no reader can be touching it now. // The `head.store(.., Release)` below is what publishes this write // to the consumer's next `Acquire` load in `pop`. unsafe { *self.messages[head].get() = msg; } self.head.store(next, Ordering::Release); true } /// Wait-free dequeue for the microkernel scheduler. /// /// Must only be called from the single consumer side of this ring. pub fn pop(&self) -> Option<IpcMessage> { let tail = self.tail.load(Ordering::Relaxed); if tail == self.head.load(Ordering::Acquire) { return None; } // SAFETY: only the consumer ever writes slot `tail`. The Acquire // load above pairs with the producer's `head.store(.., Release)`, // so the write made in `push` is visible here before we read it. let msg = unsafe { core::mem::replace(&mut *self.messages[tail].get(), IpcMessage::Empty) }; self.tail.store((tail + 1) % RING_SIZE, Ordering::Release); Some(msg) } pub fn take_overflow(&self) -> bool { self.overflow_flag.swap(false, Ordering::AcqRel) } }

//! 1 ms isochronous tick. All safety decisions happen here, before Kafka. //! V3-4: Z-acceleration (jerk) trip added alongside Z-velocity limit. use crate::ipc::{IpcMessage, SharedRingBuffer}; use fixed::types::I20F44; use qib_schema::{WATCHDOG_DEADLINE_NS, Z_VELOCITY_HARD_LIMIT}; // V3-4: Acceleration (delta-velocity per tick) hard limit. // At 1ms ticks, this is effectively m/s² units. // 5.0 units/tick → triggers on sudden impact faster than velocity alone. pub const Z_ACCEL_HARD_LIMIT: I20F44 = I20F44::from_bits(5 << 44); pub struct RobotState { pub temp: I20F44, pub halted: bool, pub cooling_until_ns: u64, pub current_epoch: u64, pub next_seq: u64, pub last_tick_ns: u64, pub last_ack_id: Option<[u8; 16]>, /// V3-4: Previous tick's Z velocity for acceleration calculation. pub last_z_vel: I20F44, } impl RobotState { pub fn new(now_ns: u64) -> Self { Self { temp: I20F44::ZERO, halted: false, cooling_until_ns: 0, current_epoch: 1, next_seq: 0, last_tick_ns: now_ns, last_ack_id: None, last_z_vel: I20F44::ZERO, // V3-4 } } } /// Called every 1 ms from the bare-metal scheduler interrupt. /// /// `rx`/`tx` are `&SharedRingBuffer`, not `&mut` — see the safety doc on /// `SharedRingBuffer` itself. This microkernel side is the sole consumer of /// `rx` and the sole producer on `tx`; the edge proxy is the mirror image. pub fn tick(state: &mut RobotState, rx: &SharedRingBuffer, tx: &SharedRingBuffer, now_ns: u64) { // ── 0. Hardware Watchdog ───────────────────────────────────────── let elapsed = now_ns.saturating_sub(state.last_tick_ns); if elapsed > WATCHDOG_DEADLINE_NS && !state.halted { state.halted = true; // Emit watchdog-trip telemetry (status sentinel via negative z_vel) let _ = tx.push(IpcMessage::Telemetry(state.temp, I20F44::ZERO)); } state.last_tick_ns = now_ns; // ── 1. Process Commands from Edge Proxy ─────────────────────────── while let Some(msg) = rx.pop() { if let IpcMessage::Command { action, duration_sec, valid_until_ns, issued_at_ns: _, min_epoch, max_epoch, sequence, command_id, } = msg { if now_ns > valid_until_ns { continue; } if state.current_epoch < min_epoch || state.current_epoch > max_epoch { continue; } if sequence < state.next_seq { continue; } state.next_seq = sequence + 1; state.last_ack_id = Some(command_id); match action { 1 => state.cooling_until_ns = now_ns + (duration_sec as u64 * 1_000_000_000), 2 => state.halted = true, _ => {} } } } // ── 2. V3-4: Hardware Fast-Path Safety — Velocity + Acceleration ─ let current_z_vel = I20F44::from_num(read_hardware_z_vel()); evaluate_motion_safety(state, current_z_vel); // ── 3. IPC Overflow → Safety Telemetry Flag ─────────────────────── let ipc_overflow = rx.take_overflow(); // ── 4. Emit Telemetry to Edge Proxy ─────────────────────────────── let temp_fixed = state.temp; let status_msg = if ipc_overflow { IpcMessage::Telemetry(temp_fixed, I20F44::from_num(-1.0)) // overflow sentinel } else { IpcMessage::Telemetry(temp_fixed, current_z_vel) }; let _ = tx.push(status_msg); } /// V3-4 safety trip decision, extracted from `tick()` so it can be unit /// tested with a controlled velocity reading instead of the hardware /// register `read_hardware_z_vel()` always returns 0.0 for. /// /// Trips (sets `state.halted = true`) if either: /// - `current_z_vel` exceeds the absolute velocity hard limit, or /// - the *change* in velocity since the previous tick (a proxy for /// acceleration/jerk) exceeds `Z_ACCEL_HARD_LIMIT` — this catches a /// sudden impact one tick *before* velocity alone would cross the /// limit. /// /// Always advances `state.last_z_vel` for the next tick's delta, and never /// un-halts a robot that was already halted (halting is sticky within a /// tick cycle; recovery happens only via an explicit command). /// /// Returns `true` if this call is what caused the trip (i.e. the robot was /// not already halted before this reading) — useful for tests and for /// emitting a one-shot "just tripped" telemetry event in a caller that /// wants one, though the current `tick()` doesn't use the return value. pub fn evaluate_motion_safety(state: &mut RobotState, current_z_vel: I20F44) -> bool { let already_halted = state.halted; let z_accel = (current_z_vel - state.last_z_vel).abs(); let velocity_trip = current_z_vel > I20F44::from_num(Z_VELOCITY_HARD_LIMIT); let accel_trip = z_accel > Z_ACCEL_HARD_LIMIT; if (velocity_trip || accel_trip) && !state.halted { state.halted = true; } state.last_z_vel = current_z_vel; !already_halted && state.halted } fn read_hardware_z_vel() -> f64 { // Replaced by actual hardware register read in production 0.0 }

//! Maps `qib_muk::ipc::SharedRingBuffer` into a POSIX shared-memory segment //! so this process (the edge proxy) and the microkernel side observe the //! exact same ring buffer. //! //! On real hardware the microkernel doesn't call `shm_open` itself — it //! maps a fixed physical memory window agreed at build/boot time (e.g. via //! a UIO/VFIO device or a linker-script-fixed address). This module is the //! Linux-hosted side of that same contract, and is also directly usable //! as-is for a QEMU/virtio-backed or fully Linux-hosted simulation of the //! microkernel talking to this proxy over real shared memory (which is //! exactly how the integration test in `tests/shm_ipc_tests.rs` exercises //! it: two independent mappings of the same name, one acting as producer, //! one as consumer, proving they observe the same underlying memory). use anyhow::{anyhow, Context, Result}; use qib_muk::ipc::SharedRingBuffer; use std::ffi::CString; use std::io; /// Opens (creating if necessary) a named POSIX shared-memory segment sized /// to hold exactly one `SharedRingBuffer`, maps it into this process, and /// returns a `'static` reference to it. /// /// Whichever caller wins the race to *create* the segment (`O_CREAT | /// O_EXCL`) is responsible for constructing a fresh `SharedRingBuffer` in /// place; every other caller attaches to the segment as-is. This avoids two /// processes racing to re-initialize (and thereby corrupt) a ring that the /// other side may already be using. /// /// # Safety /// Every process mapping the same `name` must agree on the exact layout of /// `SharedRingBuffer` (same qib-muk version/ABI), and — per /// `SharedRingBuffer`'s own safety contract — exactly one side may act as /// producer and the other as consumer for a given ring. This function /// cannot check either of those; both are caller obligations. pub unsafe fn map_shared_ring(name: &str) -> Result<&'static SharedRingBuffer> { let c_name = CString::new(name).context("shm name must not contain NUL bytes")?; let size = std::mem::size_of::<SharedRingBuffer>(); let mut created = true; let mut fd = libc::shm_open( c_name.as_ptr(), libc::O_CREAT | libc::O_EXCL | libc::O_RDWR, 0o600, ); if fd < 0 && io::Error::last_os_error().raw_os_error() == Some(libc::EEXIST) { created = false; fd = libc::shm_open(c_name.as_ptr(), libc::O_RDWR, 0o600); } if fd < 0 { return Err(anyhow!( "shm_open({name}) failed: {}", io::Error::last_os_error() )); } if created && libc::ftruncate(fd, size as libc::off_t) != 0 { let err = io::Error::last_os_error(); libc::close(fd); return Err(anyhow!("ftruncate({name}, {size}) failed: {err}")); } let ptr = libc::mmap( std::ptr::null_mut(), size, libc::PROT_READ | libc::PROT_WRITE, libc::MAP_SHARED, fd, 0, ); libc::close(fd); // safe to close once mapped; the mapping outlives the fd if ptr == libc::MAP_FAILED { return Err(anyhow!( "mmap({name}) failed: {}", io::Error::last_os_error() )); } if created { // We won the creation race: construct a fresh, correctly-initialized // SharedRingBuffer directly into the mapped memory. We must not read // the memory as a SharedRingBuffer before this — freshly-truncated // shm pages are zero-filled, which is *not* guaranteed to be a valid // bit pattern for this type (in particular, IpcMessage's enum // discriminant), so we construct it explicitly instead of assuming. std::ptr::write(ptr as *mut SharedRingBuffer, SharedRingBuffer::new()); } Ok(&*(ptr as *const SharedRingBuffer)) } /// Removes a named shared-memory segment. Intended for test teardown and /// clean process-group shutdown; on real hardware deployments the physical /// window's lifecycle is managed outside this process entirely. pub fn unlink_shared_ring(name: &str) { if let Ok(c_name) = CString::new(name) { unsafe { libc::shm_unlink(c_name.as_ptr()); } } }

//! Per-robot Bayesian Digital Twin with EWMA variance and Brier-score //! circuit breaker. Self-contained; no global mutable state. use qib_schema::{ BREAKER_RECOVERY_GOOD_READINGS, BRIER_DELTA_THRESHOLD, BRIER_Z_CONFIDENCE, EWMA_LR, VARIANCE_EPSILON, }; use std::sync::atomic::{AtomicBool, AtomicU32, Ordering}; pub struct RobotTwinState { pub robot_id: u32, pub temp_mean: f64, /// EWMA variance accumulator (Welford online algorithm) pub m2: f64, /// Circuit breaker: open = commands halted for THIS robot only pub breaker_open: AtomicBool, /// Consecutive good readings since last breaker trip (auto-recovery) pub good_readings: AtomicU32, pub last_ack_id: Option<[u8; 16]>, pub next_sequence: u64, } impl RobotTwinState { pub fn new(robot_id: u32, initial_temp: f64) -> Self { Self { robot_id, temp_mean: initial_temp, m2: 0.0, breaker_open: AtomicBool::new(false), good_readings: AtomicU32::new(0), last_ack_id: None, next_sequence: 0, } } /// V3.1: reconstructs a twin from a previously-persisted /// `TwinStateSnapshot`, used on worker startup to warm-restore state /// after a restart instead of every robot silently resetting to a /// fresh cold twin (mean re-learned from scratch, breaker force-closed, /// and — most importantly — `next_sequence` reset to 0, which would /// make every command this worker issues get silently dropped by the /// microkernel's replay-protection check, since it has already seen /// higher sequence numbers from before the restart). pub fn restore( robot_id: u32, temp_mean: f64, variance: f64, next_sequence: u64, breaker_open: bool, ) -> Self { Self { robot_id, temp_mean, m2: variance, breaker_open: AtomicBool::new(breaker_open), good_readings: AtomicU32::new(0), last_ack_id: None, next_sequence, } } /// EWMA-Welford update. Variance stays bounded; never diverges. pub fn update(&mut self, temp: f64) { let delta1 = temp - self.temp_mean; self.temp_mean += EWMA_LR * delta1; let delta2 = temp - self.temp_mean; self.m2 = (1.0 - EWMA_LR) * self.m2 + EWMA_LR * (delta1 * delta2); } /// Standard deviation with epsilon floor to prevent Z-score divide-by-zero. pub fn std_dev(&self) -> f64 { self.m2.sqrt().max(VARIANCE_EPSILON) } /// Evaluate Brier-score breaker. Returns true if tripped this call. pub fn evaluate_breaker(&self, predicted_temp: f64, actual_temp: f64) -> bool { let delta = (predicted_temp - actual_temp).abs(); let z_score = delta / self.std_dev(); if z_score > BRIER_Z_CONFIDENCE && delta > BRIER_DELTA_THRESHOLD { self.breaker_open.store(true, Ordering::SeqCst); self.good_readings.store(0, Ordering::SeqCst); return true; } if self.breaker_open.load(Ordering::SeqCst) { let good = self.good_readings.fetch_add(1, Ordering::SeqCst) + 1; if good >= BREAKER_RECOVERY_GOOD_READINGS { self.breaker_open.store(false, Ordering::SeqCst); self.good_readings.store(0, Ordering::SeqCst); } } false } pub fn is_breaker_open(&self) -> bool { self.breaker_open.load(Ordering::SeqCst) } pub fn next_seq(&mut self) -> u64 { let s = self.next_sequence; self.next_sequence += 1; s } }

//! V3-5 FIX: static, deterministic per-partition ownership. //! //! ## The bug //! The original implementation gave every `PartitionWorker` a *unique* //! consumer `group.id` (`qib-control-partition-{partition_id}`) and called //! `consumer.subscribe(&[TOPIC])`. `subscribe()` puts a consumer into //! Kafka's dynamic group-rebalance protocol: the broker's group coordinator //! decides which partitions each *group* owns, and distributes them among //! that group's members. Because each worker was the lone member of its own //! group, the coordinator handed it **every** partition of the topic — not //! just the one implied by its name. //! //! In practice this meant all N workers each consumed all messages for all //! robots, so: //! - Every robot's telemetry was processed redundantly by every worker, //! each with its own independent (and inconsistent) `RobotTwinState`. //! - The core V3-5 claim — "a robot_id always hashes to the same //! partition, so each worker has exclusive ownership, no locks needed" //! — did not hold, because ownership was never actually partitioned. //! //! ## The fix //! Use `consumer.assign(&TopicPartitionList)` for **static** partition //! ownership instead of `subscribe()`. `assign()` bypasses the //! group-rebalance protocol entirely: a consumer only ever reads the //! partitions it is explicitly given, regardless of `group.id`. Each //! worker keeps its own `group.id` purely so offsets are committed and //! tracked independently per partition; that part of the original design //! was fine; `subscribe()` vs `assign()` was the actual defect. //! //! With static assignment /// there is no coordinator to fall back on if this drifts: too few workers /// silently leaves some partitions (and their robots) completely unowned; /// a miscounted deployment could also double-assign a partition. Both are /// safety-relevant given each partition's twin state is assumed exclusive. pub fn validate_partition_count(expected: i32, actual: i32) -> Result<()> { if expected != actual { return Err(anyhow!( "KAFKA_PARTITIONS={expected} does not match actual topic partition count \ ({actual}); static assignment requires these to match exactly or some \ partitions will be left unowned" )); } Ok(()) } /// The exact, zero-indexed partition ids that `total` correctly-configured /// static workers should own between them. Used by tests to check full, /// non-overlapping coverage of the topic. pub fn expected_partition_ids(total: i32) -> Vec<i32> { (0..total).collect() } /// Queries the broker for the actual partition count of `topic`. This makes that assumption visible. /// /// Returns `Ok(true)` if `cleanup.policy` is set and contains `"compact"` /// (Kafka allows `"compact,delete"` as a combined policy), `Ok(false)` if /// it's set to something else (e.g. the default `"delete"`), and an `Err` /// if the config couldn't be fetched at all (e.g. insufficient broker /// permissions, or — as observed against `rdkafka`'s `MockCluster` — admin /// `describe_configs` simply isn't implemented in the mock broker; //! V3.1 fix (issue #2): warm-restoring per-robot digital twins from //! `TWIN_STATE_TOPIC` on worker startup, instead of every restart silently //! resetting every robot's twin to a fresh cold state. //! //! ## Why this matters //! `PartitionWorker.local_twins` previously lived only in process memory. //! A worker restart (deploy, crash) reset every owned robot's: //! - EWMA mean/variance — the breaker "forgets" what temperature is //! normal for that robot and has to re-learn it from scratch; //! - breaker_open — a robot that was correctly halted due to divergence //! comes back up as if nothing happened; //! - **`next_sequence`** — this is the sharp edge. The microkernel //! rejects any command whose `sequence < state.next_seq` (replay //! protection). If the backend restarts and starts issuing sequence //! numbers from 0 again, but the microkernel has already seen higher //! sequence numbers from before the restart, **every command this //! worker issues for that robot is silently dropped** until the //! microkernel itself is also reset — the robot becomes uncommandable //! from this worker with no visible error. //! //! ## The approach //! `TWIN_STATE_TOPIC` is already published to on every telemetry tick, //! keyed by `robot_id`, with the *exact* fields needed to reconstruct a //! twin (see `qib_schema::TwinStateSnapshot`). So the persistence store //! already exists — nothing new needs to be introduced — it just wasn't //! being read back. On startup, each worker replays its own partition of //! `TWIN_STATE_TOPIC` (same partition id as its `TELEMETRY_CONTROL_TOPIC` //! assignment, since both are keyed by `robot_id` with the same default //! partitioner and are validated to have matching partition counts) from //! the beginning up to the watermark captured at the start of replay, and //! keeps only the most recent snapshot per `robot_id` — deliberately not //! relying on Kafka log compaction having already run, since compaction is //! a best-effort background process with no delivery guarantee on timing. use std::collections::HashMap; use std::time::Duration; use anyhow::{Context, Result}; use qib_schema::TwinStateSnapshot; use rdkafka::consumer::{Consumer, StreamConsumer}; use rdkafka::Message; use tracing::{info, warn}; use crate::partition::build_partition_assignment; use crate::twin::RobotTwinState; /// Pure replay-folding logic: given raw postcard-encoded payloads **in the /// order they were consumed** (i.e. partition offset order), returns the /// most recent `RobotTwinState` per `robot_id`. /// /// Deliberately broker-independent so it's directly unit testable. A /// malformed/undecodable payload (e.g. a pre-V3.1 snapshot missing the /// `variance`/`next_sequence` fields — see the wire-format note on /// `TwinStateSnapshot`) is logged and skipped rather than aborting the /// whole replay; one bad or stale-format historical message shouldn't /// prevent every other robot's state from being restored. pub fn build_twins_from_snapshots<I>(payloads: I) -> HashMap<u32, RobotTwinState> where I: IntoIterator<Item = Vec<u8>>, { let mut twins = HashMap::new(); for payload in payloads { match qib_schema::deserialize_msg::<TwinStateSnapshot>(&payload) { Ok(snap) => { // Later messages in iteration order are more recent (we // consume in ascending offset order), so a plain insert // naturally keeps "last seen" = "most recent" per robot. twins.insert( snap.robot_id, RobotTwinState::restore( snap.robot_id, snap.temp_mean, snap.variance, snap.next_sequence, snap.breaker_open, ), ); } Err(e) => { warn!("Skipping undecodable twin-state snapshot during replay: {e}"); } } } twins } /// Replays partition `partition_id` of `topic` (expected to be /// `TWIN_STATE_TOPIC`) from the beginning up to the high watermark captured /// at the start of this call, returning the warm-restored twin map for /// this worker's robots. /// /// Returns an empty map (not an error) if the partition has no messages /// yet — a brand-new deployment has nothing to replay, and that's a /// perfectly normal cold start, not a failure. pub async fn replay_twin_snapshots( brokers: &str, topic: &str, partition_id: i32, ) -> Result<HashMap<u32, RobotTwinState>> { let consumer: StreamConsumer = rdkafka::ClientConfig::new() .set("bootstrap.servers", brokers) .set("group.id", format!("qib-twin-warmup-{partition_id}")) .set("enable.auto.commit", "false") .create() .context("warm-up consumer creation failed")?; // Capture the watermark BEFORE assigning/reading, so replay has a fixed // end point and can't run forever waiting for messages that arrive // during replay itself (those belong to the live consumption loop that // starts right after this function returns). let (low, high) = consumer .fetch_watermarks(topic, partition_id, Duration::from_secs(10)) .with_context(|| format!("failed to fetch watermarks for {topic}:{partition_id}"))?; if high <= low { info!( "No prior twin-state history for {topic}:{partition_id} — starting cold (this is normal for a new deployment)" ); return Ok(HashMap::new()); } let tpl = build_partition_assignment(topic, partition_id)?; // build_partition_assignment resumes from Offset::Stored by default // (see partition.rs), but a warm-up replay must always read from the // true beginning of the partition regardless of any previously // committed offset for this dedicated warm-up group.id, so we // override it explicitly here. let mut tpl = tpl; tpl.set_all_offsets(rdkafka::Offset::Beginning)?; consumer.assign(&tpl)?; let mut payloads = Vec::new(); loop { let msg = tokio::time::timeout(Duration::from_secs(10), consumer.recv()) .await .with_context(|| { format!("timed out replaying {topic}:{partition_id} before reaching watermark {high}") })? .with_context(|| format!("recv error while replaying {topic}:{partition_id}"))?; if let Some(payload) = msg.payload() { payloads.push(payload.to_vec()); } if msg.offset() + 1 >= high { break; } } let twins = build_twins_from_snapshots(payloads); info!( "Warm-restored {} robot twin(s) from {topic}:{partition_id} (offsets {low}..{high})", twins.len() ); Ok(twins) } #[cfg(test)] mod tests { use super::*; fn snapshot(robot_id: u32, temp_mean: f64, variance: f64, next_sequence: u64, breaker_open: bool) -> Vec<u8> { qib_schema::serialize_msg(&TwinStateSnapshot { robot_id, temp_mean, temp_stddev: variance.sqrt(), z_score: 0.0, breaker_open, timestamp_ns: 0, variance, next_sequence, }) } #[test] fn restores_fields_exactly() { let payloads = vec![snapshot(1, 72.5, 3.1, 42, true)]; assert!(twin.is_breaker_open()); } #[test] fn later_snapshot_for_the_same_robot_wins() { // Simulates two ticks for the same robot arriving in offset order: // the second (higher sequence, different mean) must be what survives. let payloads = vec![ snapshot(1, 70.0, 1.0, 10, false), snapshot(1, 85.0, 2.0, 11, true), ]; //! Cloud control center: consumes telemetry, updates per-robot digital twins, //! evaluates Brier-score circuit breakers, issues signed commands via Kafka. //! //! V3 additions: //! - PartitionWorker: each Kafka partition worker owns a private HashMap of //! twins, eliminating DashMap lock contention entirely. //! - sign_command(): contextual Ed25519 signature binding robot_id and //! command_id into the signed digest. //! - postcard: all Kafka payloads use binary wire format. //! //! V3.1 FIX (issue #1): partition ownership is now established with //! `consumer.assign()` (static) instead of `consumer.subscribe()` (dynamic //! group rebalance). See `partition.rs` for the full explanation — in short, //! `subscribe()` with a unique `group.id` per worker gave every worker every //! partition, silently defeating the "exclusive per-partition twin //! ownership" invariant this design depends on. use std::collections::HashMap; use std::time::{SystemTime, UNIX_EPOCH}; use anyhow::{Context, Result}; use qib_schema::{ CommandEvent, TelemetryEvent, TwinStateSnapshot, TELEMETRY_CONTROL_TOPIC, TEMP_ALERT_CELSIUS, TEMP_MEAN_ALERT, TWIN_STATE_TOPIC, }; use rdkafka::consumer::{CommitMode, Consumer, StreamConsumer}; use rdkafka::message::{BorrowedMessage, Header, OwnedHeaders}; use rdkafka::producer::{FutureProducer, FutureRecord}; use rdkafka::Message; use std::sync::Arc; use tokio::signal; use tracing::{error, info, warn}; use uuid::Uuid; use ed25519_dalek::SigningKey; use qib_cloud_backend::metrics; use qib_cloud_backend::partition::{ build_partition_assignment, fetch_actual_partition_count, topic_has_compaction_enabled, validate_partition_count, }; use qib_cloud_backend::twin::RobotTwinState; use qib_cloud_backend::warmup::replay_twin_snapshots; use qib_cloud_backend::{load_signing_key, sign_command}; // ── V3-5: Partition-Local Digital Twin Worker ──────────────────────── // // Each Kafka partition is owned by exactly one PartitionWorker (see the // FIXED assignment logic in `run()` below). Because a given robot_id always // hashes to the same partition (key = robot_id bytes), each worker has // *exclusive* ownership of its robot subset — no locks needed — *provided* // the underlying consumer is statically assigned that single partition, // which is what this fix restores. struct PartitionWorker { partition_id: i32, local_twins: HashMap<u32, RobotTwinState>, producer: FutureProducer, signing_key: Arc<SigningKey>, } impl PartitionWorker { /// `initial_twins` is the warm-restored state from /// `warmup::replay_twin_snapshots` (empty on a cold/new deployment — /// see that module for why this matters, particularly for /// `next_sequence` continuity). fn new( partition_id: i32, producer: FutureProducer, signing_key: Arc<SigningKey>, initial_twins: HashMap<u32, RobotTwinState>, ) -> Self { Self { partition_id, local_twins: initial_twins, producer, signing_key, } } async fn handle_message(&mut self, m: &BorrowedMessage<'_>) -> Result<()> { // No locking required: this worker is the exclusive owner of these robot IDs // now that the consumer is statically `assign()`-ed to a single partition. let payload = m.payload().unwrap_or(&[]); let tel: TelemetryEvent = qib_schema::deserialize_msg(payload).context("Telemetry deserialization failed")?; let now_ns = current_time_ns(); let robot_id_str = tel.robot_id.to_string(); let twin = self .local_twins .entry(tel.robot_id) .or_insert_with(|| RobotTwinState::new(tel.robot_id, tel.temp)); if let Some(ack_id) = tel.ack_command_id { twin.last_ack_id = Some(ack_id); } // ── 1. Brier-Score Circuit Breaker ─────────────────────────── let predicted_temp = twin.temp_mean; twin.update(tel.temp); let z_score = (predicted_temp - tel.temp).abs() / twin.std_dev(); let tripped = twin.evaluate_breaker(predicted_temp, tel.temp); if tripped { warn!( "Circuit Breaker TRIPPED for robot {} (partition {}, z={:.2}, delta={:.2}°C). \ Halting commands, routing to DLQ.", tel.robot_id, self.partition_id, z_score, (predicted_temp - tel.temp).abs(), ); metrics::BREAKER_TRIPS .with_label_values(&[&robot_id_str, "model_divergence"]) .inc(); } metrics::BREAKER_STATE .with_label_values(&[&robot_id_str]) .set(if twin.is_breaker_open() { 1.0 } else { 0.0 }); metrics::TWIN_VARIANCE .with_label_values(&[&robot_id_str]) .set(twin.m2); metrics::TWIN_ZSCORE .with_label_values(&[&robot_id_str]) .set(z_score); // ── 2.
